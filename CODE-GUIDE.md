# Как читать этот код — пособие с нуля

Это пособие — не общий курс программирования и не общий курс JavaScript.
Это объяснение КОНКРЕТНО НАШЕГО кода, начиная с абсолютных основ (что
такое переменная, что такое функция), потому что вы прямо сказали: опыта
в программировании почти нет. Все примеры внизу — не выдуманные учебные
примеры, а настоящие строчки из настоящих файлов этого репозитория, с
указанием, где именно они лежат, чтобы вы могли открыть файл и увидеть
то же самое своими глазами.

Пособие устроено слоями: от самых азов (Главы 1–6) — к тому, как эти
азы складываются в наш конкретный движок (Главы 7–12) — и к тому, как
самостоятельно проверять, что код работает, без обращения к AI
(Глава 13). Глава 14 — словарь терминов для быстрого поиска, если
где-то в тексте встретилось слово, смысл которого забылся.

**Как читать:** Главы 1–9 лучше пройти по порядку один раз — каждая
следующая использует понятия из предыдущих. Главы 10–13 можно открывать
по потребности, когда возник конкретный вопрос («как устроен файл
data.js» → Глава 10-11; «что делает вот эта функция целиком» → Глава 12).

## Глава 1 — Что вообще такое программа

Программа — это текст, написанный на языке, который умеет читать
компьютер, и который заставляет компьютер выполнить последовательность
действий. Компьютер не «понимает смысл» — он механически выполняет
СТРОКУ ЗА СТРОКОЙ ровно то, что написано, сверху вниз (с отступлениями,
о которых будет глава 5 — «условия и переходы»).

Вот самая обычная строчка из нашего кода
(`docs/app/examples/rule10-gacchati-slots.js`):

```js
const START = centeredStart(7);
```

Что здесь происходит, слово за словом:
- `const` — «я создаю именованную ячейку, и её содержимое больше не
  поменяется после этой строки» (подробнее — Глава 2).
- `START` — имя, которое я даю этой ячейке. Дальше в коде, где угодно,
  слово `START` означает «то, что мы туда положили здесь».
- `=` — «положить в ячейку то, что справа».
- `centeredStart(7)` — вызов ГОТОВОЙ функции по имени `centeredStart`
  с числом `7` (подробнее про функции — Глава 3). Функция сама
  вычисляет число и ВОЗВРАЩАЕТ его — это число и попадает в `START`.

То есть эта одна строка читается так: «посчитай, где начать раскладку
слова из 7 звуков, чтобы оно было по центру экрана, и запомни результат
под именем START, чтобы использовать его в следующих строчках».

## Глава 2 — Переменные: именованные ячейки для значений

**Переменная** — это именованная ячейка памяти. В неё можно положить
значение и потом обращаться к нему по имени, а не запоминать само
значение.

В нашем коде переменные создаются словами `const` или `let`:
- `const X = ...` — значение ячейки НЕ будет меняться после создания.
  В нашем коде это подавляющее большинство случаев — сознательный
  стиль: если что-то не должно меняться, это видно из самого объявления.
- `let X = ...` — значение МОЖЕТ поменяться позже той же ячейкой. Используется
  реже — только когда значение реально пересчитывается по ходу работы
  (например, счётчик в цикле).

**Важная тонкость**, которая будет часто встречаться: `const` защищает
только САМУ ячейку от переприсваивания, но не то, что внутри объекта
или массива (Глава 4) может измениться. Пример
(`docs/app/lib/slot-engine-cube.js`):

```js
const cube = {};
cube.mesh = new THREE.Mesh(getCubeGeo(), cube.matsMain);
```

`cube` объявлен через `const` — но строчкой ниже мы спокойно ДОБАВЛЯЕМ
в него поле `mesh`. Это не противоречие: `const` запрещает написать
`cube = {...}` (заменить САМ объект целиком) чуть позже, но не запрещает
менять то, что лежит ВНУТРИ этого объекта.

### Какие виды значений встречаются в нашем коде

- **Число** (`number`): `1300`, `0.22`, `-0.45`. Без кавычек.
- **Строка** (`string`): `'ch'`, `'transform'`, `"rgba(160,160,160,.55)"`.
  В кавычках (у нас — почти всегда одинарные `'...'`) — это текст, а не
  число и не код.
- **Логическое значение** (`boolean`): `true` или `false`. Например,
  `op.quiet` — либо `true` (эффект «тихий»), либо не задано вообще
  (тогда движок считает, что «обычный»).
- **Объект** и **массив** — «контейнеры» из нескольких значений сразу.
  Про них — целая следующая глава, потому что именно ими описаны ВСЕ
  данные наших примеров (`data.initial`, `data.steps`, `data.ops`).

Пример настоящей строки с несколькими типами разом
(`docs/app/lib/slot-engine-ops-elide.js`):

```js
const riseDur = op.riseDur ?? 1300; // тот же темп, что у split
```

`op.riseDur` — попытка достать число из объекта `op` (Глава 4). `??` —
это отдельный оператор «если слева пусто/не задано, возьми то, что
справа» (подробнее в Главе 5). Итог: если в данных примера `riseDur` не
указан явно — движок использует число `1300` (миллисекунд) по
умолчанию.

## Глава 3 — Функции: переиспользуемые именованные рецепты

**Функция** — это именованный кусок кода, который можно вызвать (то
есть заставить исполниться) сколько угодно раз, передав ему разные
исходные данные (**аргументы**/**параметры**) и получив назад результат
(**возвращаемое значение**).

Настоящий пример, целиком (`docs/app/lib/slot-engine-core.js`):

```js
export function slotX(i) { return (i - (N_SLOTS - 1) / 2) * SLOT; }
```

Разбор:
- `export` — «эту функцию можно использовать из ДРУГИХ файлов» (см.
  Главу 7 про `import`/`export`).
- `function slotX(i) { ... }` — определение функции с именем `slotX`,
  у которой один параметр — назвали его `i` (это просто имя, при вызове
  туда попадёт то, что передал вызывающий код).
- `return (...)` — «функция ЗАКАНЧИВАЕТСЯ здесь и возвращает вызывающему
  коду вот это число».

Если где-то в коде написано `slotX(3)` — это ВЫЗОВ: параметр `i`
временно становится равен `3`, функция считает формулу и возвращает
число — мировую координату X слота номер 3.

### Стрелочные функции — короткая запись «мини-функции на месте»

Очень часто функцию не нужно называть отдельным именем — она нужна
только «здесь и сейчас», как аргумент для чего-то ещё. Для этого есть
короткая запись — **стрелочная функция** (`=>`). Настоящий пример
(`docs/app/lib/slot-engine-ops-influence.js`):

```js
const sources = sourceSlots.map(s => cubes[s]).filter(Boolean);
```

`.map(s => cubes[s])` означает: «для КАЖДОГО элемента списка
`sourceSlots` (назовём временно каждый элемент `s`) — возьми
`cubes[s]» — это и есть стрелочная функция, читается как «дан `s`,
верни `cubes[s]`». `.map`/`.filter` — методы массивов, разбираются
подробно в Главе 4.

### Функция может принимать несколько параметров

Настоящий пример — заголовок функции `applyElide`
(`docs/app/lib/slot-engine-ops-elide.js`):

```js
export function applyElide(op, elapsed, ctx) {
```

Три параметра: `op` (данные конкретной операции — объект, Глава 4),
`elapsed` (число — сколько миллисекунд прошло с начала анимации),
`ctx` (общий «контекст» — ещё один объект, в котором лежат все нужные
вещи вроде списка кубиков, камеры и т.п.). Про то, КТО и КАК вызывает
эту функцию каждый кадр — Глава 9 и Глава 11.

## Глава 4 — Массивы и объекты: как устроены наши данные

Всё содержимое каждого примера правила (какие буквы падают, что с ними
происходит и когда) описано именно объектами и массивами — если вы это
поймёте, вы сможете прочитать ЛЮБОЙ файл `docs/app/examples/*.js`.

### Массив — пронумерованный список

Массив — упорядоченный список значений, пронумерованный с нуля (не с
единицы!). Пишется в квадратных скобках `[...]`, элементы через запятую.

Настоящий пример — список операций правила 10
(`docs/app/examples/rule10-gacchati-slots.js`, немного упрощено для
показа структуры):

```js
ops: [
  { type: 'influence', from: START + 1, to: START + 3, start: 3220 },
  { type: 'bud', from: START + 3, to: START + 2, toGlyph: 'ch', start: 5720 },
  { type: 'transform', at: START + 2, toGlyph: 'c', start: 8920 },
]
```

Это массив из ТРЁХ элементов. Элемент номер 0 (первый) — объект
`{ type: 'influence', ... }`. Элемент номер 1 — `{ type: 'bud', ... }`.
Элемент номер 2 — `{ type: 'transform', ... }`. Движок потом обходит
этот список и для каждого элемента решает, «наступило ли уже его время»
(по полю `start`) и что с ним делать (по полю `type`) — см. Главу 11.

Обращение к элементу массива по номеру — через квадратные скобки:
`arr[0]` — первый элемент, `arr[1]` — второй, и так далее. Настоящий
пример (`docs/app/lib/slot-engine-ops-move.js`):

```js
const p = flyArcPosition(arr.from, slotX(arr.newSlot), 0, 0, t, arr.arcHeight ?? 1.0);
```

(здесь `arr` — не массив, а один ЭЛЕМЕНТ массива arrivals, назван так
внутри `.forEach`-цикла — имя переменной может быть любым, программист
сам придумывает удобное имя).

### Объект — набор полей с именами

Объект — контейнер, где у каждого значения есть СВОЁ ИМЯ (**ключ**), а
не номер. Пишется в фигурных скобках `{...}`, поля через запятую, у
каждого поля — `имя: значение`.

Настоящий пример (`docs/app/examples/rule11-aganva-slots.js`):

```js
{ type: 'transform', at: START + 3, toGlyph: 'n', start: 5300 }
```

Это ОДИН объект с четырьмя полями: `type` (равно строке `'transform'`),
`at` (равно числу — результату сложения `START + 3`), `toGlyph` (равно
строке `'n'`), `start` (равно числу `5300`).

Обращение к полю объекта — через точку: `op.type`, `op.at`, `op.start`.
Настоящий пример (`docs/app/lib/slot-engine-ops-transform.js`, смысл):
если у вас есть объект-операция `op`, то `op.toGlyph` достаёт из него
именно поле `toGlyph` — новую букву, в которую должен превратиться
кубик.

**Если поля нет вообще** (не было указано при создании объекта) — при
обращении получится специальное значение `undefined` («не определено»,
не ошибка, но и не полезное число). Именно от этого защищает `??`
(Глава 5) — «если получилось `undefined`, возьми вот такое значение по
умолчанию».

### Объекты и массивы можно вкладывать друг в друга

Всё «дерево данных» одного примера — это ОДИН большой объект с тремя
полями, где `steps` и `ops` — сами являются массивами ОБЪЕКТОВ. Вот
почти полный реальный файл целиком, чтобы увидеть структуру сразу всю
(`docs/app/examples/rule11-aganva-slots.js`, сокращено):

```js
export const data = {
  initial: [
    { slot: START + 0, tr: 'a' },
    { slot: START + 1, tr: 'g' },
    // ... ещё 4 таких же объекта, по одному на букву
  ],
  steps: [
    { kind: 'rule', ruleNum: 11, start: 2600, end: 7300, activeSlots: [START + 3, START + 4] },
  ],
  ops: [
    { type: 'influence', from: START + 4, to: START + 3, start: 2700 },
    { type: 'transform', at: START + 3, toGlyph: 'n', start: 5300 },
  ],
};
```

Читаем по уровням: `data` — объект с тремя полями (`initial`, `steps`,
`ops`). `data.initial` — МАССИВ объектов, каждый описывает одну падающую
букву (поле `slot` — номер места, поле `tr` — сама буква). `data.steps`
— массив объектов, каждый описывает один «шаг» показа (когда он
начинается/кончается, какие слоты подсвечены). `data.ops` — массив
объектов, каждый описывает одно КОНКРЕТНОЕ действие (влияние, превращение
и т.п.) — что именно каждый тип действия означает, разбирает Глава 11.

### Деструктуризация — быстрый способ «распаковать» объект

Очень частая конструкция в нашем коде — взять НЕСКОЛЬКО полей объекта
разом, каждое в свою переменную, одной строкой. Настоящий пример
(`docs/app/lib/slot-engine-ops-elide.js`):

```js
const { cubes } = ctx;
```

Это ТО ЖЕ САМОЕ, что написать `const cubes = ctx.cubes;` — просто более
короткая, привычная в JavaScript запись. Если нужно несколько полей
разом — они перечисляются через запятую внутри фигурных скобок:

```js
const { cubes, wordGroupsList } = ctx;
```

— читается «достань из `ctx` поле `cubes` в переменную `cubes`, и поле
`wordGroupsList` в переменную `wordGroupsList`».

## Глава 5 — Условия, циклы и «безопасные» операторы

### if / else — развилка

`if (условие) { ... }` выполняет блок в скобках ТОЛЬКО если условие
истинно (`true`). `else` — что делать, если условие оказалось ложно.

Настоящий, очень частый паттерн — «ранний выход» (`docs/app/lib/slot-engine-ops-elide.js`):

```js
if (elapsed < op.start) return;
```

Читается: «если время `elapsed` (сколько мс прошло) МЕНЬШЕ времени
начала операции `op.start` — значит, действие ещё не должно начаться —
`return` немедленно ЗАКАНЧИВАЕТ выполнение функции на этом месте, ничего
дальше в этот раз не делая». Такая строка почти в начале КАЖДОЙ
`apply*`-функции (Глава 9 объясняет, почему функция вызывается КАЖДЫЙ
кадр, а не один раз).

Более сложная развилка на три ветки, настоящий пример
(`docs/app/lib/slot-engine-ops-elide.js`, структура упрощена — убраны
детали внутри веток):

```js
if (elapsed <= riseEnd) {
  // ветка А: буква ещё опускается в отстойник
} else if (elapsed <= fadeStart) {
  // ветка Б: буква висит на месте, полностью видна
} else {
  // ветка В: буква тает и исчезает совсем
}
```

Ровно одна из трёх веток выполнится на данном кадре — какая из них
зависит от того, в какой момент времени (`elapsed`) мы сейчас
находимся относительно границ `riseEnd`/`fadeStart`.

### Циклы через методы массива — `.forEach`, `.map`, `.filter`

Вместо классического «цикла for» наш код почти всегда использует методы
самого массива — то есть готовые команды «сделай вот это для КАЖДОГО
элемента списка».

- `.forEach(x => { ... })` — «выполни это действие для каждого элемента,
  ничего не собирая обратно». Настоящий пример
  (`docs/app/lib/slot-engine-ops-shared.js`):

  ```js
  sources.forEach(src => setFacePulse(src, radiusFrac, 0.85 * envelope, ringRgb));
  ```

  Для каждого элемента списка `sources` (по одному, называя его временно
  `src`) — вызвать функцию `setFacePulse` с этими параметрами.

- `.map(x => ...)` — «для каждого элемента посчитай новое значение и
  собери их все в НОВЫЙ список того же размера». Уже видели выше:
  `sourceSlots.map(s => cubes[s])`.

- `.filter(x => ...)` — «оставь только те элементы, для которых
  выражение истинно, остальные выбрось». `.filter(Boolean)` (тоже уже
  видели выше) — специальный частый приём: «выбрось все `null`/
  `undefined`/пустые значения, оставь только настоящие».

### `??` и `?.` — операторы «на случай пустоты»

- `a ?? b` — «если `a` равно `null` или `undefined` (то есть НЕ
  задано) — возьми `b` вместо него; если `a` реально задано (даже
  числом `0` или пустой строкой) — возьми `a`». Уже видели:
  `op.riseDur ?? 1300`.
- `a?.b` — «если `a` существует — возьми его поле `b`; если `a` не
  существует (`null`/`undefined`) — не пытаться и не упасть с ошибкой,
  просто получить `undefined`». Защита от «обращения к полю
  несуществующей вещи».

## Глава 6 — Строки с «вставками» и разворачивание списков

### Шаблонные строки — текст с вычисленными кусками внутри

Обычная строка в кавычках — просто текст. Но иногда нужно текст, внутри
которого — значение переменной. Для этого — строка в ОБРАТНЫХ кавычках
(`` ` ``, не `'` и не `"`), а вставка значения — в `${...}`.

Настоящий пример (`docs/app/lib/slot-engine-ops-shared.js`):

```js
ring.style.borderColor = `rgba(${rgbStr},.55)`;
```

Если `rgbStr` в этот момент равен строке `"160,160,160"`, то итоговая
строка получится `"rgba(160,160,160,.55)"` — обычный CSS-цвет с
прозрачностью 0.55. `${rgbStr}` — «сюда вставь ЗНАЧЕНИЕ переменной
rgbStr в момент выполнения», а не текст `rgbStr` буквально.

### Многоточие (spread) — разворачивание готового набора полей

Три точки `...` перед объектом означают «возьми ВСЕ поля из этого
объекта и подставь их сюда по одному», а не «этот объект целиком как
одно поле».

Настоящий пример (`docs/app/examples/rule10-gacchati-slots.js`):

```js
{ type: 'transform', at: START + 2, toGlyph: 'c', start: 8920, ...TRANSFORM_KIND.vargaPair, clearance: 0 }
```

`TRANSFORM_KIND.vargaPair` — готовый, заранее заданный объект где-то в
`slot-engine-core.js`, например `{ spinTurns: 0.5, signal: 'blank' }`.
`...TRANSFORM_KIND.vargaPair` здесь означает: «возьми оба этих поля
(`spinTurns` и `signal`) и добавь их прямо в наш объект», как если бы мы
вручную написали `spinTurns: 0.5, signal: 'blank'` в этом же месте. Это
экономит от необходимости переписывать одни и те же числа руками в
каждом примере — используется именно готовый, один раз проверенный
набор.

## Глава 7 — ES-модули: как файлы обращаются друг к другу

Наш проект — не один огромный файл, а много маленьких файлов
(`docs/app/lib/slot-engine-core.js`, `slot-engine-cube.js`, и т.д.),
каждый отвечает за свою часть. Чтобы функция/переменная, объявленная в
одном файле, стала доступна в другом — используются `export` и
`import`.

- `export function X() {...}` (или `export const X = ...`) в файле A —
  «сделай X видимым для других файлов».
- `import { X } from './файл-A.js';` в файле B — «возьми X из файла A и
  дай мне сюда возможность его использовать под тем же именем».

Настоящий пример начала файла (`docs/app/lib/slot-engine-cube.js`):

```js
import * as THREE from 'three';
import { buildChalkMaterials, buildMetallicMaterials, makeChalkGeo, makeShadowBlobTexture } from './chalk-module.js';
import { CUBE_SIZE, READY_COLOR, colorFor } from './slot-engine-core.js';
```

Три отдельные строки `import`:
1. `import * as THREE from 'three';` — «возьми ВСЁ из библиотеки `three`
   (это внешняя библиотека 3D-графики — Three.js) и назови это всё
   `THREE`» — дальше в файле `THREE.Mesh`, `THREE.Vector3` и т.п.
2. Вторая строка — «возьми именно эти четыре конкретные вещи из файла
   `chalk-module.js` (который лежит в той же папке — `./` означает
   „рядом“)».
3. Третья — то же самое из `slot-engine-core.js`.

### Барабан-файл — один файл, который просто пересобирает остальные

`docs/app/lib/slot-engine.js` — особый файл: он сам почти ничего не
делает, а просто говорит «возьми ВСЁ, что экспортировано из каждого из
этих файлов, и сделай видимым отсюда тоже» — настоящее содержимое:

```js
export * from './slot-engine-core.js';
export * from './slot-engine-cube.js';
export * from './slot-engine-words.js';
// ...и так далее, по одной строке на каждый файл движка
```

`export * from './X.js'` — «экспортируй отсюда ВСЁ, что экспортировано
там». Благодаря этому весь остальной код (примеры правил, тестовые
страницы, приложение) пишет одно простое `import { ... } from
'../lib/slot-engine.js'` — и получает доступ к функциям из ЛЮБОГО из
внутренних файлов движка, не зная и не заботясь, в котором именно из
них эта функция на самом деле лежит.

## Глава 8 — Браузер: минимум про HTML, DOM и события

Наше приложение — веб-страница. У страницы есть **DOM** (Document
Object Model) — дерево всех видимых элементов (заголовков, кнопок,
блоков), с которым JavaScript может разговаривать: найти элемент,
прочитать/изменить его содержимое, повесить на него реакцию на клик.

### Найти элемент на странице

`document.getElementById('имя')` — «найди на странице элемент с этим
`id` (уникальной меткой в HTML) и дай мне на него ссылку». Настоящий
пример (`docs/app/alpha-panel.js`):

```js
const tooltip = document.getElementById('tooltip');
```

Теперь переменная `tooltip` — это «пульт управления» тем самым блоком
на странице (у которого в HTML написано `id="tooltip"`). Через него
можно, например, поменять текст: `tooltip.textContent = 'новый текст'`.

### Повесить реакцию на действие пользователя

`элемент.addEventListener('тип-события', функция)` — «когда произойдёт
это событие на этом элементе — выполни вот эту функцию». Настоящий
пример (`docs/app/alpha-panel.js`):

```js
document.addEventListener('click', () => {
  // код внутри выполнится КАЖДЫЙ РАЗ, когда пользователь кликнет
  // где угодно на странице
});
```

`'click'` — тип события. `() => { ... }` — стрелочная функция (Глава 3)
без параметров — «что делать, когда это случится».

### Почему нельзя просто открыть HTML-файл двойным кликом

Наши файлы используют `<script type="module">` — это способ подключить
JavaScript, который умеет `import`/`export` (Глава 7). Браузеры не
разрешают загружать модули через прямое открытие файла (`file://`) —
нужен локальный веб-сервер (подробности — `ARCHITECTURE.md`, раздел
«Быстрый старт»).

## Глава 9 — Three.js на пальцах: как рисуется 3D

Наш 3D-движок использует библиотеку **Three.js** — готовый инструмент
для рисования трёхмерной графики в браузере. Вам не нужно знать её
целиком — достаточно нескольких понятий, которые постоянно встречаются
в коде.

- **Сцена (`scene`)** — контейнер, в который кладутся все 3D-объекты,
  которые должны быть видны.
- **Камера (`camera`)** — точка, откуда «смотрят» на сцену; у неё есть
  позиция и угол обзора (`fov`).
- **Геометрия (`geometry`)** — форма объекта (например, куб).
- **Материал (`material`)** — то, ЧЕМ покрыта поверхность (цвет,
  текстура-рисунок буквы, прозрачность, металлический блеск и т.п.).
- **Мэш (`mesh`, от «mesh» — сетка)** — геометрия + материал ВМЕСТЕ,
  готовый объект, который можно поместить в сцену и увидеть.

Настоящий пример создания кубика (`docs/app/lib/slot-engine-cube.js`):

```js
cube.mesh = new THREE.Mesh(getCubeGeo(), cube.matsMain);
```

«Создай новый мэш из формы (что вернёт `getCubeGeo()`) и материала
(`cube.matsMain`), и положи его в поле `mesh` объекта `cube`».

### Позиция, поворот, масштаб

У каждого мэша есть три главных свойства, которые двигают/крутят/
меняют его размер на экране:

- `mesh.position.x` / `.y` / `.z` — где объект находится (три
  координаты — влево-вправо, вверх-вниз, ближе-дальше).
- `mesh.scale` — размер (`1` = обычный, `0.5` = в два раза меньше).
- `mesh.rotation` или `mesh.quaternion` — поворот. Кватернион
  (`quaternion`) — просто другой, более надёжный внутренний способ
  описания поворота в 3D (без «путаницы порядка осей», которая бывает
  у простых углов) — в нашем коде его почти всегда меняют через готовые
  функции библиотеки, вручную считать не нужно.

Настоящий пример (`docs/app/lib/slot-engine-cube.js`):

```js
cube.shadow.position.x = cube.mesh.position.x + 0.08;
```

«Поставь тень чуть правее (`+0.08`) от самого кубика по оси X» — типичная
строчка, которая КАЖДЫЙ КАДР пересчитывает, где должна быть тень,
следуя за настоящим кубиком.

### Кадровый цикл — откуда берётся «анимация»

Ключевая идея всего движка: НЕТ отдельного «проигрывателя», который
запоминает кадры заранее. Вместо этого браузер примерно 60 раз в
секунду (~каждые 16 миллисекунд) вызывает одну и ту же функцию заново
— и она КАЖДЫЙ РАЗ пересчитывает, «а где всё должно быть ПРЯМО СЕЙЧАС»,
исходя из того, сколько миллисекунд прошло с начала (`elapsed`).

Поэтому во ВСЕХ `apply*`-функциях (`applyElide`, `applyTransform` и
т.д.) первым делом всегда написана математика вида «сколько мс прошло
→ какая доля пути пройдена → какая позиция ей соответствует» — а не
«шаг 1, потом шаг 2, потом шаг 3». Одна и та же функция вызывается
СОТНИ раз за одну анимацию, и каждый раз просто СЧИТАЕТ заново, где
сейчас должен быть кубик, вместо того чтобы «помнить», что было в
прошлый раз.

## Глава 11 — Как один пример превращается в анимацию: путь от файла до экрана

Проследим ВЕСЬ путь одного правила от данных до движущихся кубиков,
используя всё, что вы уже узнали.

**Шаг 1. Пользователь кликает карточку правила** в левой панели. Код в
`rule-panel.js` (используя DOM-события из Главы 8) смотрит, есть ли у
этого правила поле `module` в `EXAMPLES[n]` (объект/массив данных, Глава 4,
файл `data.js`).

**Шаг 2. Если поле есть** — оно содержит СТРОКУ-путь, например
`'./examples/rule10-gacchati-slots.js'`. Код динамически ИМПОРТИРУЕТ
этот файл (тот же `import`, что в Главе 7, только вызванный из кода, а
не написанный заранее) и вызывает его функцию `mount(container)`.

**Шаг 3. `mount(container)` вызывает `mountSlotExample(container,
data)`** (`slot-engine-mount.js`) — передавая туда контейнер (DOM-элемент,
куда рисовать) и весь объект `data` этого примера (Глава 4 — то самое
`{initial, steps, ops}`).

**Шаг 4. `mountSlotExample`:**
- Проверяет данные через `validateExampleData(data)` — если в `ops`
  есть опечатка (например, забыли обязательное поле) — здесь выскочит
  понятная ошибка ДО того, как что-то начнёт рисоваться.
- Создаёт сцену, камеру, и по одному кубику (`makeCube`, Глава 9) на
  каждую букву из `data.initial`.
- Запускает кадровый цикл (Глава 9) — функцию, которая вызывается
  ~60 раз в секунду.

**Шаг 5. На КАЖДОМ кадре** кадровый цикл смотрит, сколько миллисекунд
прошло (`elapsed`), и для КАЖДОГО объекта в `data.ops` (массив, Глава 4)
вызывает СВОЮ `apply*`-функцию, в зависимости от поля `type`:
- `type: 'influence'` → вызывается `applyInfluence(op, elapsed, ctx)`
- `type: 'transform'` → вызывается `applyTransform(op, elapsed, ctx)`
- `type: 'elide'` → вызывается `applyElide(op, elapsed, ctx)`
- ...и так далее, для каждого из 10 типов операций (полный список — в
  `ARCHITECTURE.md`, таблица «Как работает один пример»).

**Шаг 6. Каждая `apply*`-функция** первым делом проверяет (`if
(elapsed < op.start) return;`, Глава 5) — «моё время ещё не пришло?» —
если да, ничего не делает в этом кадре. Если время пришло — считает,
какая доля пути (`t`, число от 0 до 1) уже пройдена, и меняет
`position`/`scale`/материал кубика (Глава 9) СООТВЕТСТВЕННО этой доле.

Вот и весь механизм: НЕТ отдельного «проигрывателя анимации» — есть
только данные (`data.ops`, что и когда должно случиться) и функции,
которые 60 раз в секунду спрашивают «а что должно быть видно ПРЯМО
СЕЙЧАС», исходя из этих данных и текущего времени.

## Глава 12 — Построчный разбор настоящей функции целиком: `applyElide`

Это самая практическая глава: полный, построчный разбор ОДНОЙ настоящей
функции нашего движка — `applyElide` (файл
`docs/app/lib/slot-engine-ops-elide.js`). Цель — не выучить именно эту
функцию наизусть, а увидеть на реальном примере, КАК читать любую
похожую функцию самостоятельно.

Функция описывает эффект «буква исчезает без замены» (используется,
например, когда конечный `-s` пропадает в правиле 15 — śādhi). Полный
код (тот же, что в файле, с разбивкой на пронумерованные блоки для
объяснения):

```js
export function applyElide(op, elapsed, ctx) {
  const { cubes } = ctx;
  if (elapsed < op.start) return;
  const cube = cubes[op.at];
  if (!cube || op._done) return;
```

**Блок 1.** `const { cubes } = ctx;` — деструктуризация (Глава 4):
достаём из общего контекста `ctx` список всех кубиков сцены, называем
его `cubes`. `if (elapsed < op.start) return;` — ранний выход (Глава 5):
время этой операции ещё не пришло, ничего не делаем. `const cube =
cubes[op.at];` — достаём из списка кубиков (объект, Глава 4, где ключи
— номера слотов) именно тот кубик, который должен исчезнуть (`op.at` —
номер его слота). `if (!cube || op._done) return;` — ещё один ранний
выход: `!cube` означает «кубика там уже нет» (может, его уже удалили —
дальше увидим, где), `op._done` — «эта операция уже полностью
завершилась раньше», `||` — «или» (если ХОТЯ БЫ ОДНО из двух истинно —
выходим). Заметьте: `op._done` — это ПОЛЕ, которое сама функция создаёт
и меняет у объекта `op` по ходу работы (объекты можно так дополнять,
Глава 2) — способ «запомнить» между кадрами, что уже произошло.

```js
    if (!op._impactAt) {
      op._impactAt = elapsed;
      spawnPulseRing(frontAnchor(cube.mesh), 700, op.impactColor ?? GROUP_RGB, ctx);
    }
```

**Блок 2.** «Момент удара» — вспышка РОВНО в момент начала эффекта, не
позже. `if (!op._impactAt)` — «если этого поля ещё не было» (в первый
раз, когда функция дошла до этого места, `op._impactAt` равно
`undefined`, что в условии считается «ложью» — отсюда `!` перед ним,
«не»). Внутри: `op._impactAt = elapsed;` — запоминаем момент времени,
КОГДА это произошло (чтобы не повторить вспышку на следующем кадре —
условие выше станет ложным). `spawnPulseRing(...)` — вызов готовой
функции (из другого файла, `slot-engine-ops-shared.js`) — рисует
кольцо-вспышку. `op.impactColor ?? GROUP_RGB` (Глава 5) — «если в
данных явно указан цвет вспышки — использовать его, иначе — обычный
нейтральный цвет».

```js
    const riseDur = op.riseDur ?? 1300;
    const holdDur = op.holdDur ?? 800;
    const fadeDur = op.fadeDur ?? 1100;
```

**Блок 3.** Три числа-настройки (в миллисекундах): сколько длится
погружение вниз (`riseDur`), сколько буква висит в отстойнике, ещё
видимая (`holdDur`), и сколько длится финальное угасание (`fadeDur`). У
каждого — значение «по умолчанию», если в данных конкретного примера
не указано другое.

```js
    if (op.label && !op._labelSpawned) {
      op._labelSpawned = true;
      spawnLabelPill(op.label, op.at, false, riseDur + holdDur + fadeDur, ctx);
    }
```

**Блок 4.** Пилюля-подпись (например, слово «lopa» над/под кубиком).
`op.label` — «если в данных задан текст подписи» (если поле не задано —
`undefined`, что тоже считается «ложью»). `!op._labelSpawned` — «и
подпись ещё не была создана» (тот же приём «запомнить через поле
объекта», что и в Блоке 2). `riseDur + holdDur + fadeDur` — простое
сложение чисел: подпись должна быть видна ровно всё время жизни буквы,
целиком.

```js
    const holdOffset = op.holdOffset ?? { x: -0.45, y: -2.2, z: -0.4 };
    const basePos = new THREE.Vector3(slotX(op.at), 0, 0);
    const holdPos = basePos.clone().add(new THREE.Vector3(holdOffset.x, holdOffset.y, holdOffset.z));
    const riseEnd = op.start + riseDur;
    const fadeStart = riseEnd + holdDur;
```

**Блок 5.** Геометрия пути. `holdOffset` — объект (Глава 4) с тремя
координатами смещения (куда именно «утонуть» относительно исходного
места). `new THREE.Vector3(...)` (Глава 9) — «точка в 3D-пространстве».
`basePos` — исходное место буквы (по оси X — через `slotX`, функцию из
Главы 3; Y и Z — ноль, на общем уровне ряда). `holdPos` — конечная
точка отстойника: берём исходную точку (`.clone()` — «сделай КОПИЮ, не
трогай саму basePos») и добавляем к ней смещение. `riseEnd`/`fadeStart`
— МОМЕНТЫ ВРЕМЕНИ (не расстояния!) — когда заканчивается погружение и
когда начинается угасание, посчитанные простым сложением уже известных
чисел.

```js
    if (elapsed <= riseEnd) {
      const t = clamp01((elapsed - op.start) / riseDur);
      const te = easeInOutCubic(t);
      cube.mesh.position.lerpVectors(basePos, holdPos, te);
      setOpacity(cube.mesh, 1);
    } else if (elapsed <= fadeStart) {
      cube.mesh.position.copy(holdPos);
      const idle = (elapsed - riseEnd) * 0.0022;
      cube.mesh.position.y += Math.sin(idle) * 0.06;
      setOpacity(cube.mesh, 1);
    } else {
      // ... (третья ветка — угасание, разберём отдельно ниже)
    }
```

**Блок 6.** Развилка из трёх веток (Глава 5) — какая сейчас фаза.

- *Ветка А* (`elapsed <= riseEnd`, идёт погружение): `(elapsed -
  op.start) / riseDur` — «сколько мс прошло С НАЧАЛА операции, поделить
  на общую длительность погружения» — получаем ДОЛЮ пути от 0 (только
  начали) до 1 (уже дошли). `clamp01(...)` (функция из Главы 3,
  `slot-engine-core.js`) — «не дай числу выйти за пределы 0..1, даже
  если из-за неровного кадра получилось чуть больше/меньше». `te =
  easeInOutCubic(t)` — не РАВНОМЕРНОЕ движение, а с плавным разгоном и
  торможением (готовая математическая формула — «плавность», упомянута
  в Главе 2). `cube.mesh.position.lerpVectors(basePos, holdPos, te)` —
  «поставь позицию кубика МЕЖДУ `basePos` и `holdPos`, на доле `te`
  пути» (`lerp` = «linear interpolation», линейная интерполяция —
  промежуточная точка между двумя точками). `setOpacity(cube.mesh, 1)`
  — прозрачность полная (буква всё ещё чётко видна, пока опускается).

- *Ветка Б* (буква висит на месте, видима): `cube.mesh.position.copy(holdPos)`
  — позиция ЖЁСТКО равна точке отстойника (уже не двигаемся вдоль
  пути). `idle`/`Math.sin(idle) * 0.06` — небольшое лёгкое покачивание
  вверх-вниз (синус — стандартная математическая функция для «плавных
  волнообразных колебаний»), чтобы буква не выглядела «замороженной»
  идеально неподвижно.

- *Ветка В* (угасание) — разберём отдельно следующим блоком, она самая
  насыщенная.

```js
      if (!op._fadeStartedAt) {
        op._fadeStartedAt = elapsed;
        if (!op.quiet) spawnSparkleBurst(frontAnchor(cube.mesh), ctx, undefined, ringColorFrom(colorFor(cube.tr)));
      }
      const t = clamp01((elapsed - fadeStart) / fadeDur);
      if (op.quiet) {
        setOpacity(cube.mesh, lerp(1, 0, t));
      } else {
        const visT = clamp01(t * 1.8);
        setOpacity(cube.mesh, lerp(1, 0, visT));
        cube.mesh.scale.setScalar(lerp(1, 0.12, easeOutCubic(visT)));
      }
      if (t >= 1) {
        op._done = true;
        cube.mesh.visible = false;
        delete cubes[op.at];
      }
```

**Блок 7 (ветка В, угасание).** Тот же приём «запомнить момент через
поле объекта» (Блок 2), теперь для момента начала угасания:
`op._fadeStartedAt`. `if (!op.quiet) spawnSparkleBurst(...)` — искры
разлетаются, НО ТОЛЬКО если в данных НЕ указан «тихий режим»
(`op.quiet`) — вспоминаем `!` = «не». `ringColorFrom(colorFor(cube.tr))`
— вложенный вызов: сначала `colorFor(cube.tr)` узнаёт «настоящий»
фонетический цвет ЭТОЙ КОНКРЕТНОЙ буквы (`cube.tr` — какая буква
записана в этом кубике), потом `ringColorFrom(...)` превращает этот цвет
в формат, подходящий для искр.

Дальше — снова развилка `if (op.quiet) { ... } else { ... }`: в «тихом»
режиме — просто плавно гаснет (`lerp(1, 0, t)` — прозрачность едет от 1
до 0 равномерно вдоль всего `fadeDur`). В обычном режиме — гаснет
БЫСТРЕЕ (`t * 1.8` — «пройти путь в 1.8 раза быстрее, чем формально
длится `fadeDur`», значит визуально всё уже закончилось раньше, а
`clamp01` не даст уйти за границу 1) И ОДНОВРЕМЕННО сжимается
(`cube.mesh.scale.setScalar(...)` — единый масштаб по всем трём осям
сразу, едет от `1` (обычный размер) до `0.12` (почти точка)).

Наконец: `if (t >= 1)` — «путь угасания пройден полностью» —
`op._done = true` (запоминаем навсегда — это отключит функцию через
ранний выход в самом Блоке 1 на всех будущих кадрах), `cube.mesh.visible
= false` (перестать РИСОВАТЬ этот мэш вообще — Глава 9), `delete
cubes[op.at]` — «удали ключ `op.at` (номер слота) из объекта `cubes`
целиком» — буквы больше не существует даже в данных, не только на
экране.

```js
    if (op._impactAt != null && !op._done && elapsed < fadeStart) {
      const pt = clamp01((elapsed - op._impactAt) / 350);
      cube.mesh.scale.setScalar(lerp(1.25, 1, easeOutCubic(pt)));
    }
}
```

**Блок 8 (уже ПОСЛЕ развилки из Блока 6, выполняется на каждом кадре
независимо от того, какая ветка сработала выше).** Это отдельный,
короткий «скачок масштаба» ровно в момент удара (Блок 2) — кубик на
мгновение становится чуть крупнее (`1.25`) и плавно возвращается к
обычному размеру (`1`) за 350 мс. Условие `elapsed < fadeStart`
специально не даёт этому блоку работать ОДНОВРЕМЕННО с угасанием из
Блока 7 (там масштаб считается по-своему) — иначе они бы «спорили» за
одно и то же свойство кубика на одном кадре, и выигрывал бы тот код,
что физически написан ПОЗЖЕ в файле (эта функция явно проверяет,
чтобы такого конфликта не было).

**Вот и вся функция.** 132 строки (с комментариями), а по сути — три
идеи: (1) ранние выходы в начале — «моё ли сейчас время», (2) развилка
на фазы по времени — «в какой момент своей жизни находится эффект прямо
сейчас», (3) в каждой фазе — простая арифметика «доля пройденного пути
→ позиция/прозрачность/масштаб».

## Глава 13 — Как самому проверить, что код работает, без AI

Все команды ниже выполняются в терминале (открывается в VSCode, или
через `Пуск → Терминал`) из папки проекта.

### `npm test` — запустить все автоматические проверки

```bash
npm test
```

Через несколько секунд вы увидите список строк вида:
```
✔ имя теста (0.1234ms)
```
Значок `✔` — тест прошёл успешно. Если что-то не так, вместо `✔` будет
`✖` и текст, ЧТО именно тест ожидал и что получил на самом деле. В
самом конце — итог:
```
ℹ tests 236
ℹ pass 236
ℹ fail 0
```
`pass` должно равняться общему числу `tests`, `fail` — быть `0`. Если
`fail` не ноль — что-то в коде реально сломано, и вывод выше подскажет,
в каком именно тесте и почему.

### `node --check <файл>` — быстрая проверка «не опечатался ли я»

```bash
node --check docs/app/examples/rule10-gacchati-slots.js
```

Если файл написан синтаксически правильно (правильно расставлены
скобки, запятые и т.п.) — команда ничего не выведет (тишина = всё
хорошо). Если есть опечатка — выведет текст ошибки С УКАЗАНИЕМ файла и
номера строки, где компьютер «споткнулся».

### `npm run lint` — поиск подозрительных мест в коде

```bash
npm run lint
```

Находит вещи вроде «объявили переменную и никогда её не использовали»
— не обязательно ошибка, но почти всегда признак, что что-то забыто
или лишнее. Если всё чисто — вывод пустой.

### Что означает «стек ошибки» (stack trace)

Если код падает по-настоящему (не просто lint-предупреждение), в
терминале появится текст вида:

```
TypeError: Cannot read properties of undefined (reading 'mesh')
    at applyElide (docs/app/lib/slot-engine-ops-elide.js:17:20)
```

Это читается снизу вверх как «путь, как мы сюда попали»: САМАЯ ВАЖНАЯ
строка — первая после слова `at` (`at applyElide (...)`) — она говорит,
В КАКОМ файле и на какой СТРОКЕ (`:17`) произошла ошибка. Текст до
этого (`TypeError: Cannot read properties of undefined...`) — что
именно пошло не так («пытались прочитать поле `mesh` у чего-то, что
оказалось `undefined`» — то есть кубик, который мы ждали найти, не
нашёлся). Это ровно тот навык, который позволяет самостоятельно найти
МЕСТО проблемы, даже не понимая всей логики целиком — файл и номер
строки указаны прямо в сообщении.

### Безопасный порядок действий при любой правке

1. Сделайте правку.
2. `node --check <файл>` — на файле, который правили (ловит опечатки
   мгновенно, до всего остального).
3. `npm test` — убедиться, что ничего из уже работавшего не сломалось.
4. `npm run lint` — на всякий случай.
5. Только после того, как все четыре шага чистые — открывать в браузере
   и смотреть глазами (визуальную красоту ни один тест не проверяет —
   это единственное, что остаётся на ваше собственное зрение).

## Глава 14 — Мини-словарь терминов

- **Переменная** — именованная ячейка для значения (Глава 2).
- **Константа** (`const`) — переменная, которую нельзя переприсвоить
  после создания (но если внутри объект — его ПОЛЯ менять можно).
- **Функция** — именованный переиспользуемый кусок кода, принимает
  аргументы, может вернуть результат (Глава 3).
- **Аргумент / параметр** — значение, переданное функции при вызове.
- **Стрелочная функция** (`x => ...`) — короткая запись функции «на
  месте», без отдельного имени (Глава 3).
- **Массив** (`[...]`) — пронумерованный (с нуля) список значений
  (Глава 4).
- **Объект** (`{...}`) — набор полей с именами (Глава 4).
- **Метод** — функция, которая «принадлежит» объекту/массиву и
  вызывается через точку (`.forEach`, `.map`, `.filter`).
- **Деструктуризация** — способ разом достать несколько полей объекта
  в отдельные переменные: `const { a, b } = obj;` (Глава 4).
- **Оператор `??`** — «если слева пусто — возьми значение справа»
  (Глава 5).
- **Оператор `?.`** — «безопасное» обращение к полю, не упадёт с
  ошибкой, если слева ничего нет (Глава 5).
- **Шаблонная строка** (`` `текст ${переменная} текст` ``) — строка со
  вставленными вычисленными значениями (Глава 6).
- **Spread / многоточие** (`...obj`) — «разверни все поля объекта сюда
  по одному» (Глава 6).
- **`import`/`export`** — как один файл делает свой код доступным
  другому файлу (Глава 7).
- **Модуль** — файл, который использует `import`/`export`.
- **DOM** — дерево видимых элементов веб-страницы, с которым может
  разговаривать JavaScript (Глава 8).
- **Событие** (`event`) — действие пользователя (клик, и т.п.), на
  которое можно повесить реакцию (Глава 8).
- **Сцена / камера / мэш / геометрия / материал** — базовые понятия
  3D-графики Three.js (Глава 9).
- **Кватернион** — способ описывать поворот объекта в 3D (Глава 9).
- **Кадровый цикл** — функция, которую браузер вызывает ~60 раз в
  секунду, каждый раз пересчитывающая текущее состояние анимации
  (Глава 9).
- **`elapsed`** — сколько миллисекунд прошло с начала анимации примера
  (главный «часовой» параметр почти каждой функции движка).
- **Интерполяция (`lerp`)** — вычисление промежуточной точки между
  двумя значениями по доле пути (0 = начало, 1 = конец).
- **Плавность (easing)** — математическая формула, делающая движение
  неравномерным (с разгоном/торможением) вместо линейного.
- **Ранний выход** (`if (...) return;`) — способ прекратить выполнение
  функции досрочно, если условие для дальнейшей работы не выполнено
  (Глава 5).
- **Тест** — небольшой автоматический кусок кода, который проверяет,
  что другой код делает именно то, что задумано (Глава 13).
- **Линтер** (`lint`) — инструмент, ищущий подозрительные (не
  обязательно ошибочные) места в коде.
- **Стек ошибки** (`stack trace`) — текст, который печатает компьютер
  при падении программы, указывающий файл и строку, где это произошло
  (Глава 13).
