# Тесты

Настоящие, постоянные тесты — не одноразовые проверки в чате. Запускаются
локально через встроенный тестраннер Node (без внешних зависимостей типа
Jest/Vitest — тот же принцип минимализма, что и во всём проекте).

## Запуск

```bash
npm install   # один раз — ставит three как dev-зависимость (см. ниже)
npm test
```

## Что покрыто сейчас

Каждый файл тестов привязан к КОНКРЕТНОЙ, реально пойманной за сессию
ошибке — не абстрактным «на всякий случай»:

- `colorFor.test.mjs` — придыхательные согласные (kh/gh/.../dh) и дифтонги
  ai/au не должны получать нейтральный цвет сжатого блока (регрессия
  заходов 48-49).
- `buildRuntimeSteps.test.mjs` — проявление между шагами цепочки правил с
  одинаковым составом участников не должно вставляться вообще (регрессия
  захода 52 — асимметрия прозрачности до 0.128 у одной и той же буквы в
  двух позициях ряда).
- `transformKind.test.mjs` — категории `transform` (парная замена внутри
  варги / общая ассимиляция под соседа) дают ТОЧНО те `spinTurns`/`signal`,
  что задуманы (регрессия захода 46 — угол поворота был перепутан).

## Известное ограничение — что НЕ покрыто и почему

Самая содержательная часть движка — обработчики операций (`applyTransform`,
`applyElide`, `applyInfluence`, `applyApproach`, `applyMerge`, `applySplit`,
`applyStepDim` и весь кадровый цикл) — определены ВНУТРИ функции
`mountSlotExample`, не на уровне модуля. Это значит: их физически нельзя
импортировать и протестировать напрямую без переноса на уровень модуля
(с явной передачей состояния — `cubes`, сцены и т.п. — параметрами вместо
захвата через замыкание). Это отдельная, более рискованная работа
(следующая стадия профессионализации, см. `algoritm-agnayas-shablon.md` /
`emeneau-project-handoff.md`), сознательно не сделана в рамках этого
захода — риск тихо сломать уже отлаженную анимацию выше, чем цена
отложить.

До тех пор вся проверка этих функций — по-прежнему ручная численная
симуляция (см. историю сессии), не автоматизированный тест.

## Про версию `three` в devDependencies

Реальная версия в браузере — r128, вендорена локально
(`docs/app/vendor/three.module.js`), НЕ через npm. Пакет из
`node_modules` нужен только чтобы `import * as THREE from 'three'`
резолвился при запуске тестов в Node — протестированные здесь функции
(`colorFor`, `buildRuntimeSteps` и т.п.) сами THREE.* не вызывают, так что
расхождение версий тестам не мешает.
